Chapter 8 User Manual

This chapter explains how to install the Manzil prototype, start the dashboard, run a simulation, dispatch
an ambulance, and close a road, and how to repeat the experiments of Chapter 9 from the command
line. The dashboard is the single-page interface implemented in FYP-I; it combines the essential parts
of wireframes G01, G02, and G04 in Section 4.8. Every value it shows comes from a live SUMO run;
nothing on the screen is mocked.

8.1 Installation and Start-up

The prototype runs on Windows or Linux with Python 3.10 or newer and Node.js for building the dash-
board; no GPU is needed. After cloning the repository, the following commands create the environment,
install the pinned packages including SUMO, build the dashboard, and start the service:

python -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev,api]"
.venv\Scripts\python -m pip install -e ".[rl]"

      --extra-index-url https://download.pytorch.org/whl/cpu
cd dashboard && npm install && npm run build && cd ..
.venv\Scripts\python -m manzil.api

The installation line with [rl] is only needed for the DQN controller; without it the dashboard lists
the DQN as unavailable. The service then serves the dashboard at http://127.0.0.1:8000, which is
opened in a web browser. Figure 8.1 shows the start screen: the map of the 3×3 grid on the left and the
control panel on the right.

8.2 Running a Simulation

The RUN panel selects the signal controller (fixed-time, adaptive, or DQN), the demand profile (light,
medium, heavy, or uneven), the random seed, and the run length in seconds. Start run launches SUMO;
the header then shows the status, the simulation clock, and the chosen settings, and the speed slider
changes how fast the run proceeds relative to real time. On the map, each signal is coloured green,
yellow, or red at its stop line, small marks are vehicles, and roads are shaded amber when at least three
vehicles queue and purple when at least eight queue, as explained in the legend at the bottom (Figure
8.2). Stop ends the run; its records are written to a run folder under runs/live/.

8.3 Dispatching an Ambulance and Closing a Road

The AMBULANCE panel selects the origin and destination roads and whether the green corridor is used.
Dispatch ambulance inserts the ambulance and computes its first route, which is drawn in blue. The
panel then shows the mission status, the route version and what caused it, the ambulance's current road,
speed, and number of stops, and the corridor state of each junction it is using, with a log of corridor
events. Junctions held for the ambulance are marked with a ring. Only one ambulance can be active at a
time.

To test rerouting, a road is selected by clicking it on the map and closed with the INCIDENT panel.
A closed road is marked with a red cross. If it lies on the ambulance's remaining route, a new route
version with the trigger "closure" appears at once, and corridor requests that no longer lie on the route
are cancelled (Figure 8.3). When the ambulance reaches its destination, the mission status changes to
ARRIVED and the panel shows its response time next to the free-flow time (Figure 8.4).

8.5 Conclusion

The prototype is installed with a few commands and operated from one browser page: a run is started
with a chosen controller, demand, and seed, an ambulance is dispatched between two roads, and a road
can be closed to trigger rerouting while the corridor state is shown live. The same experiments as in
Chapter 9 can be repeated from the command line. The full five-screen interface of Section 4.8 is
planned for FYP-II.
